## What changed

Adds an eighth binding rule, `response-style.md` — the universal floor for how the agent *shapes a reply* (lead with the action, number multi-step work, one thread at a time, concrete estimates, no preamble/recap/closers), distinct from `implementation-quality.md`, which governs the *work* behind the reply. It applies to every response, not just code tasks, so `template/CLAUDE.md` also gains an always-loaded "Response style" summary section plus a Rules-pointer entry.

`/sync` copies the new `response-style.md` rule into `.alice/rules/` automatically (Tier 1 add). The `template/CLAUDE.md` changes need a manual merge because adopters customize that file — hence this migration.

## Automatic actions

None. The new rule file lands via the normal tiered file-copy; the CLAUDE.md changes are adopter-customized and handled in the manual checklist below.

## Manual actions

- [ ] Confirm `.alice/rules/response-style.md` now exists after this sync (it should have copied as a Tier 1 add).
- [ ] Add a Rules-pointer entry for `response-style.md` to your repo-root `CLAUDE.md` (see `template/CLAUDE.md` "Rules pointer" for the wording).
- [ ] Add the always-loaded "Response style" section to your repo-root `CLAUDE.md` — copy it from `template/CLAUDE.md` (section titled "Response style", between "Working style" and "Critical gotchas") and adapt the summary bullets to your house voice if needed.
- [ ] If your `CLAUDE.md` already documents reply/formatting conventions, reconcile them: keep project-specific voice in `CLAUDE.md`, let `response-style.md` carry the universal floor.
