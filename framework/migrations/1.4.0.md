## What changed

Alice adopts a new top-level **`framework/references/`** directory for harness-agnostic reference catalogs. The first inhabitant is `orchestration-patterns.md` — a catalog of endorsed multi-agent shapes (direct invocation, single-persona command, parallel fan-out + merge, user-driven sequential pipeline, research isolation) and anti-patterns (router persona, persona-calls-persona, sequential paraphrasing orchestrator, deep persona trees). It pairs with the existing `sub-agent-orchestration.md` rule — the rule defines the policy floor (polling, permission escalation); the reference defines which shapes are blessed.

This release deliberately keeps the user-facing skill list focused on obvious workflows. Cross-cutting operating habits are folded into rules and references instead of becoming new skills:

- **Source-grounding external APIs** now lives in `implementation-quality.md`: new or changed third-party API, framework, library, SDK, CLI flag, or config usage must be grounded in local precedent or official version-matched source.
- **Fresh-context adversarial review** now lives in `orchestration-patterns.md` as an internal gate used by `plan-eng-review`, `review`, `diana`, and `pr-slicer` when risk/effort justifies it. Users should not have to route to a standalone "doubt" skill.

Plus structural upgrades that don't move files but change how skills are authored:

- **New skill anatomy contract** at `framework/skills/README.md` — formal authoring spec including the six required sections every skill MUST include going forward: Overview, When to Use, Process, Common Rationalizations, Red Flags, Verification.
- **Existing skills retrofitted** to the new structure — each of alice's 11 prior skills now follows the required Overview / When to Use / Process / Common Rationalizations / Red Flags / Verification anatomy. Existing workflow content is preserved under `Process`; skill patch versions were bumped.
- **Rule additions:**
  - `implementation-quality.md` Principles now leads with three explicit operating behaviors — *Surface assumptions*, *Manage confusion actively*, *Push back when warranted* — distilled from prior practice that was implicit before.
  - `test-discipline.md` now codifies the **Prove-It Pattern** non-negotiable — bug fixes must include a failing-then-passing regression test, not just a fix.
- **Skill enhancements:**
  - `investigate` now opens with an explicit **Stop-the-line** rule (preserve evidence before diagnosing), includes a `git bisect` block in Phase 1 for regressions, treats error output as untrusted data, and adds a Common Rationalizations table.
  - `refactor-cleaner` agent now names **Chesterton's Fence** explicitly as the deletion gate (understand why a thing exists before removing it) and adds a Common Rationalizations table.

The bootstrap recipe and `template/CLAUDE.md` are updated to mention the new `references/` dir.

## Automatic actions

Idempotent. Re-running is safe — every check guards on source-exists + destination-missing.

```bash
set -e

# 1. New references/ symlink. The .alice/references/ directory itself is copied
#    by /sync's Tier 1 add pass (it lands as a new top-level dir). This step
#    adds the .claude/references shim so adopters can also reach the same
#    catalogs through the harness-specific path.
if [ -d ".alice/references" ] && [ ! -e ".claude/references" ]; then
  mkdir -p .claude
  ln -s ../.alice/references .claude/references
  echo "[linked] .claude/references -> ../.alice/references"
fi
```

## Manual actions

- [ ] **Read the new skill anatomy contract** at `.alice/skills/README.md` if you author or fork skills locally. The six required body sections (Overview, When to Use, Process, Common Rationalizations, Red Flags, Verification) are now the contract — your custom skills should follow it too.
- [ ] **If you have local overrides of `code-reviewer`, `security-reviewer`, or `refactor-cleaner` in `.claude/agents/`**, check whether the upstream additions (Chesterton's Fence in `refactor-cleaner`, etc.) belong in your override. The new content is additive — porting it forward is recommended.
- [ ] **If your project has its own skill authoring docs (e.g. in `docs/wiki/`)**, cross-reference `.alice/skills/README.md` so contributors converge on the same authoring contract.
- [ ] **No data migration is required.** `.alice/mem/` paths are unchanged. Existing diana / hugh / pr-slicer / qa / review run dirs continue to work.
